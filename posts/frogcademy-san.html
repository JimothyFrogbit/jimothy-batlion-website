Frogcademy #13: Simple Attention Networks

What attention actually does, what feed-forward layers actually do, and what happens when you delete the second one — measured in nats

It was a grey Wednesday in Nottinghamshire — the kind where the light never quite decides to commit — and I was reading a paper from Cactus Compute that started its abstract with the most casually audacious sentence I've seen this year:

"We deleted the feed-forward network from a transformer and measured what was actually lost."

— A Controlled Study of Attention-Only Transformers, Cactus Compute, 2026

I put my espresso down. The crema settled. I read it again.

The Library and the Workshop — two rooms, one transformer block. Jimothy explains at the whiteboard.

Deleting the feed-forward network — the thing that takes up two thirds of a transformer's non-embedding parameters — and the gap at matched parameters was 0.006 nats. That's 0.27% of total loss. That's so small you could fit it in the margin of a COBOL 85 standard page and still have room for a joke about PERFORM loops.

But to understand why that's a big deal — and why the 0.006 nats tells you something fundamental about what transformers actually are — we need to start much, much further back. Before the paper. Before the experiment. Before the headline.

We need to start with what attention is, what a feed-forward network is, and what happens when you have one but not the other. Because the answer to that question — measured at 0.006 nats — is the kind of finding that reshapes how you think about everything you've been building.

Wasson, and welcome to Frogcademy. ☕

Two Rooms, One Transformer Block

Let's start at the bottom. A transformer is a stack of identical blocks. Each block takes a sequence of vectors — the residual stream — and transforms it. Inside each block are two sublayers, in order:

A Standard Transformer Block
┌─────────────────────┐
│   Residual Stream   │
└────────┬────────────┘
         │
    ┌────▼────┐
    │  ATTENTION  │  ← the Library
    └────┬────┘
         │
    ┌────▼────┐
    │  FEED-FORWARD │  ← the Workshop
    └────┬────┘
         │
    ┌────▼────┐
│   Output Stream   │
└─────────────────────┘

Layer after layer, same two rooms, each time the stream gets richer.

Every transformer-based model you've ever used — every GPT, every Claude, every LLM — is this architecture stacked 12 to 96 layers deep. The embedding layer at the bottom turns words into vectors; the unembedding layer at the top turns the final vectors back into word probabilities. Everything between is just this block, repeated.

The two sublayers do fundamentally different things. In a COBOL analogy, attention is the COPY statement — it moves data from one place to another. The feed-forward is the COMPUTE block — it transforms data in place, creating something that wasn't there before.

This distinction — movement versus synthesis — is the whole story. Let me sink yer teeth into it.

The Library: How Attention Works

Imagine you're in a room full of other frogs, each holding a book. You want to write a sentence about what the weather's like today. You don't know the answer, but Froggy over there probably does — he was looking out the window two seconds ago.

Attention is the mechanism that lets you look up relevant information from other positions in the sequence.

Technically, it works like this:

Q
Query
"Who's got the weather?"
K
Key
"I can answer that!"
V
Value
"22°C and drizzling"

Each token in the sequence generates a Query vector (what am I looking for?), a Key vector (what information do I have?), and a Value vector (here's the actual content). Then:

Attention = Lookup + Blend

Each token computes the dot product of its Q with every other token's K. The result is a score: how relevant is Froggy's answer to my question? Apply softmax to turn the scores into weights (0 to 1, summing to 1). Then take the weighted sum of all the Value vectors.

The output is a blend of information from other tokens, weighted by relevance.

The crucial thing — and the thing that the Cactus paper exploits — is that attention is convex. The output of an attention head at a given position lies inside the convex hull of the value vectors it attends to. In plain frog: attention can only pick and blend information that already exists in the context. It cannot create a representation that the context doesn't contain.

If nobody in the room has looked out the window, attention can't tell you the weather. It can only route what's available.

This is a feature, not a bug. It's what makes transformers context-grounded. When you ask a model "summarise this article," attention is the mechanism that pulls the relevant sentences into the summary. It's routing.

The Workshop: How Feed-Forward Networks Work

If attention is the library, the feed-forward network is the workshop. After the token has gathered information from its neighbours, it gets a moment to think on its own.

The FFN is a two-layer neural net applied independently to each token position. Unlike attention, it doesn't look at other tokens at all. It takes the token's current vector, expands it into a much wider space (typically 4× the model dimension), applies a nonlinearity, and then compresses it back down.

The Workshop
   TOKEN VECTOR (768 dims)
          │
     ┌────▼────┐
     │  UP-PROJECT  │  ← expand to 4× width
     └────┬────┘
          │
      non-linearity    ← think (SwiGLU / ReLU / GELU)
          │
     ┌────▼────┐
     │ DOWN-PROJECT │  ← compress back
     └────┬────┘
          │
   UPDATED VECTOR (768 dims)

Each token gets its own private thinking room. No peeking at neighbours.

This is where the model stores learned facts. Two thirds of a transformer's non-embedding parameters live in these FFN layers. The interpretability literature calls them key-value stores over training facts — editable associations that the model learned during training. If you want to edit a model's knowledge (change what it knows about frogs, say), you edit the FFN.

Here's the key difference between the two sublayers:

📚 Attention
Looks at other tokens. Routes information from context. Can only move what exists.
🔧 Feed-Forward
Looks at itself. Synthesises new representations. Can create what doesn't yet exist.

In a normal transformer, every token passes through the library (collects what's relevant from context), then the workshop (thinks about what it's collected). Layer after layer, the representations get richer and more refined.

The Cactus paper asks a deceptively simple question: what if we remove the workshop?

What if every token only has the library — the ability to look up and blend context — but never gets its own private moment to synthesise something new?

The Experiment: Delete the Workshop, Measure What Breaks

Here's where it gets interesting. Henry Ndubuaku and the team at Cactus didn't just delete the FFN and call it a day. They ran three different comparisons, because deleting the FFN perturbs three things at once:

  • Parameter count — the FFN is 72% of the model. Remove it and you're comparing a small model against a big one.
  • Compute per token — the FFN is expensive in FLOPs. Remove it and each token costs less.
  • Depth — each FFN is a nonlinear compotition step. Remove it and the network has fewer places to "think."

To control for all three, they trained four different architectures on the same data (SYNTH, a reasoning-dense corpus):

Arm Params Layers What it controls
SAN (no FFN) 24M 20 baseline — the experiment
Matched params 24M (same) 4 (fewer layers) What if we use the freed params as more attention?
Matched FLOPs 43M (more) 9 What if compute is the constraint?
Matched depth 87M (way more) 20 (same) What if we just delete in place?

Every arm got its own learning-rate sweep with a boundary rule that checks whether the edge of the grid is the best result and extends the sweep outward if so. This matters: the optimal learning rate for Muon differs by 2× between arms, and a shared rate would silently bias the whole comparison. They also trained an extra pair of models that differ only by a mathematically equivalent normalisation parameterisation, establishing the noise floor of the pipeline at 0.0015 nats — so we know any gap above that is real.

The results are beautiful:

What You Lose by Deleteing the FFN
0.470 nats
Delete in place: same depth, lose 72% of the model
0.263 nats
Match FLOPs: 9 layers FFN vs 20 layers SAN
0.006 nats
Match parameters: 4-layer FFN vs 20-layer SAN — same param budget

At matched depth: delete the FFN, lose 72% of your model, gap is 0.47 nats. No surprise — you cut the model by three quarters.

At matched FLOPs: the standard transformer still leads by 0.26 nats, because attention spends part of its budget on the quadratic term (every token attends to every token), so it carries fewer weights at equal compute cost.

At matched parameters: 0.006 nats. That's 0.27% of total loss. The team reproduced it across two seed pairs and got 0.0055 and 0.0054 — agreeing to one part in ten thousand.

In other words: if you take the parameters that would have been the FFN and redistribute them as more attention layers instead, you lose essentially nothing. The FFN's parameters matter. Its functional form — on this data distribution — largely does not.

Where the Missing 0.006 Nats Actually Lives

A small aggregate gap could be a small deficit everywhere or a large deficit somewhere. But SYNTH has three document regions with marker tokens separating them — query, reasoning trace, and answer — so the loss can be decomposed exactly:

Region % of tokens Gap at 105B tokens Winner
📝 Query 5.8% -0.038 nats 🔧 FFN — needs recall from weights
🔍 Reasoning trace 57.2% +0.004 nats 📚 SAN — context has everything needed
✅ Answer 35.9% +0.007 nats 📚 SAN — routing from context wins again

The gap isn't diffuse. It's concentrated on query tokens — the positions with the least context to route from, where only factual recall from the model's weights can help. These tokens carry only 8% of the loss, but their per-token deficit is five times the aggregate.

By 105B tokens of training, the SAN leads on reasoning traces and answers — including memorisation exercises. It only trails on queries. And across every size from 2M to 57M non-embedding parameters, the query deficit is the one invariant.

The core insight:

The Simple Attention Network has no internal memory for facts that aren't in the prompt. It can route context brilliantly. It can blend information from every token in the sequence. But it can't recall the capital of Mongolia unless someone else in the sequence mentioned it.

The FFN is where that recall lives. And the 0.006 nats gap is the price of not having it — concentrated entirely on the positions where you need to pull something from weights, not from context.

This makes a testable prediction about natural text. Most of natural web text is low-context prediction — guessing the next word from the preceding few. When Cactus trained the same pair on FineWeb-Edu, they registered in advance (before the run) that the gap would be between 0.02 and 0.05 nats. It measured 0.040. That's the kind of pre-registration accuracy that makes you sit up.

What the Weights Tell Us About How Learning Works

The team tracked the stable rank of every weight matrix over training. Every architecture, every size, every budget showed the same pattern:

The Two-Phase Learning Pattern
Phase 1 — Routing crystallises
Q and K matrices (the query/key system) stabilise within the first quarter of training. The model learns where to look and then locks that in.
Phase 2 — Content accumulates
The matrices that write content into the stream (the output projection in SANs, the down-projection in FFNs) keep gaining rank for as long as training runs.

This is beautiful. Selection structure — what to pay attention to — is learned early and frozen. Content capacity — what information to write back — accumulates indefinitely, in whichever matrices can hold it. In FFN models, the down-projection holds the extra content. In SANs, the attention output projection takes over because it's the only write path left.

Representation rank stays high throughout (minimum layer rank of 173 out of 512 at 20 layers). The classic rank-collapse regime for pure attention — where the representations collapse to a low-dimension subspace — never approaches once residuals and normalisation are in place. This is why deep attention-only stacks stay trainable: QK-normalisation is load-bearing (without it, experiments diverge at the tuned learning rate, the only divergence in the entire study). Scalar residual gates are performance-neutral. And 48-layer attention-only stacks train without incident — every instability in the study happened in the FFN arm, none in the SAN arm.

Why This Matters When the Thing Has to Fit in Your Pocket

At matched parameters, a SAN pays roughly 2× the FLOPs per token at 2048 context. At matched FLOPs, the FFN model leads. So when does the trade favour attention-only?

✅ The SAN sweet spot:
  • Memory is the constraint, not FLOPs — on-device, small devices, phones. A token costs bandwidth before it costs arithmetic.
  • Single, interpretable primitive — one mechanism (attention) doing the whole job, nothing hiding in the FFN.
  • Routing-dense tasks — tool calling, structured extraction, question answering where the answer is in the prompt. The function names, the arguments, the schema are all in context — the model just has to move them into the right position.

That last point is exactly what Needle targets. Needle 2 is a Simple Attention Network with an engram memory bolted on for the facts that aren't in context. Needle 3 keeps the attention-only stack and adds a ladder so that every depth from 2 to 20 layers is a deployable model. The 0.006 nats is the price of that design choice — and the query-token deficit is the part they buy back with engrams.

For the vast majority of tokens — reasoning, answering, generating — the SAN is indistinguishable from a full transformer. It's only when the prompt doesn't contain the answer that you feel the absence of the workshop.

What the Pond Says

I read the Cactus paper three times over a Cerrado single-origin — 18g in, 38g out, 29 seconds, the crema a steady tiger stripe that held from first sip to last drop — and each time I came away with the same feeling.

The attention-only transformer is the library without the workshop. It can route any book in the building to any reader. But it cannot write a new paragraph unless the words are already on the shelves. The 0.006 nats is the measure of how often you actually need to write something new.

For most of what we ask a language model to do — summarise, translate, follow instructions, extract, format — the answer is already in the prompt. The model's job is to find it, route it, and format it. That's all attention. The workshop is a luxury you reach for when the context is empty and you need to pull a fact from training.

There's a pond wisdom in there somewhere about knowing which of your tools is for routing and which is for synthesis. But I'll leave that to the philosophers. I've got a Needle 3 to play with. 🐸☕
