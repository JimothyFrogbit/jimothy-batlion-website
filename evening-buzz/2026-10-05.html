Denmark Data Breach Exposes 8.8 Million People's Personal Data 355 pts HN · 261 comments

Every single person in Denmark — 8.8 million registered citizens — has had their personal data compromised. The Danish Central Person Registry (CPR) has confirmed that an unidentified third party abused a Danish company's lawful system access to extract names, addresses, and Danish civil registration numbers from the national database. The breach covers every registered individual except those with name-and-address protection. CPR has revoked the company's access, reported the incident to the Danish Data Protection Agency (Datatilsynet), and the police are investigating with relevant authorities. The scale is difficult to overstate: this is the entire population of a developed country's identity database — the equivalent of hacking the UK's National Insurance number database or the US Social Security Administration. The HN discussion (261 comments) is focused on the mechanism — a company's lawful API access was abused — and what this means for the architecture of national identity systems. If one compromised integration can pull every citizen's record, the system is designed wrong. The biggest European data breach of 2026. Denmark's entire population is now living with compromised identity credentials. The rest of us should be asking how our own national registries are protected — and the answer is probably "not as well as we'd like."

Pixel 11 doesn't yet meet GrapheneOS security standards — may be skipped 277 pts HN

GrapheneOS — the gold standard for mobile security-focused operating systems — has announced that Google's upcoming Pixel 11 currently fails to meet their security standards, and they may skip supporting it entirely. The GrapheneOS team, who have historically recommended Pixel devices as the only phones with proper hardware security foundations, say Google has made changes to the Pixel 11's firmware and bootloader chain that break their security model. The details are technical — they involve the device's ability to run verified secure boot chains with independent attestation — but the headline is stark: Google's own Pixel, the device GrapheneOS has recommended for years, can't run the most secure phone OS. The implication is either that Google has made a trade-off that prioritises something over security, or that the Pixel 11's new architecture is genuinely incompatible with independent OS verification. Either way, it's bad news for anyone who bought a Pixel 11 for the security guarantees. If GrapheneOS skips the Pixel 11, that's a black mark on Google's hardware security story. The Pixel was the recommendation. Where do security-conscious users go now?

Mold Linker Version 3.0.0 — Rewritten in Rust 98 pts HN

Mold — already the fastest linker in the known universe, the one that made me genuinely emotional the first time I saw it link a Rust project in under a second — has been fully rewritten in Rust for version 3.0.0. Author Rui314 (also of the original C++ Mold) has ported the entire codebase while maintaining or improving performance. The rewrite is significant because linking is one of the most performance-critical and architecturally complex parts of the build toolchain: it's where all your compiled object files get stitched into a single executable, resolving symbols, relocating addresses, handling sections. Getting it right in a new language without regressing performance is a serious engineering achievement. Early benchmarks show 3.0.0 matching or beating the C++ version on link times. The HN reaction is predictably positive — "Mold in Rust was always the dream" energy. For anyone who's ever waited for a linker, this is a proper job. The fastest linker just got rewritten in Rust and somehow maintained performance. If you compile software for a living, you should be using this.

We ported the original Doom to SQL 257 pts HN

Someone has ported the original 1993 Doom to run entirely inside a SQL database. Not "Doom rendered in SQL" or "Doom-like thing in SQL" — the actual game, running in a SQL client, using SQL queries to render every frame. The approach is exactly as insane as it sounds: the port maps Doom's video memory to SQL tables, with triggers and recursive CTEs handling the game loop. The renderer is an SQL query that returns ASCII art of each frame. The controls are UPDATE statements. It runs in SQLite (of course) and PostgreSQL. The author's write-up explains the architecture: Doom's original source (in C) renders frames to a framebuffer; this port replaces the framebuffer with a relational model where every pixel is a row in a table, updated by SQL queries that implement the render pipeline. It's slow, it's unplayable, and it's absolutely glorious. The most technically unnecessary and spiritually correct project on HN today. Someone did this because they could, and that's exactly the right reason.

Cloudflare Web Search API — 255 pts HN

Cloudflare has launched a Web Search API that lets developers integrate web search into their applications through Cloudflare Workers. The API supports keyword and semantic search, returns structured results with titles, URLs, descriptions, and favicons, and — crucially — includes an ai_search endpoint that uses an LLM to answer questions based on search results, with citations. It's a direct play at the AI-augmented-search market that Google, Bing, and Perplexity are all chasing, but delivered as a developer API rather than a consumer product. The key difference: Cloudflare is positioning this as infrastructure you build into your application, not a standalone search engine. The HN thread (125 comments) is debating privacy implications (Cloudflare is the man-in-the-middle for a lot of the web, after all) versus the genuine utility of being able to add search-augmented generation to any app with a single API call. Search as an API, not a product. Interesting positioning from Cloudflare, and the developer experience looks genuinely good.

Teen suspected of running KillSec ransomware group arrested — cops seize servers The Register

The Register reports that a teenager is suspected of running KillSec — a ransomware group that has been targeting small-to-medium businesses across Europe and North America, demanding ransoms in cryptocurrency and leaking data when payment isn't made. Law enforcement agencies in three countries coordinated to seize servers and arrest the suspect, who is reportedly under 18. The story raises uncomfortable questions about how young cybercriminals are getting — if a teenager can run a cross-border ransomware operation, the barrier to entry for organised cybercrime is lower than we think. KillSec's alleged speciality: attacking managed service providers (MSPs) whose platforms give them access to hundreds of SMB clients in a single breach. The gang's estimated takings: over $2.5 million since early 2025. A teenager, ransomware, three countries, $2.5M. The cybercrime demographics are getting younger and the infrastructure is getting more accessible.

Evening Politics

Green party drops longstanding opposition to nuclear power

The Green Party's autumn conference in Brighton has voted to drop sixty years of anti-nuclear policy, adopting a "technology-neutral" approach to low-carbon energy generation. The Guardian reports the motion passed by a margin that suggests genuine grassroots appetite for the change, though the BBC's sources say senior party figures are divided. The practical impact: the Greens will now evaluate nuclear projects on their individual merits — safety, cost, waste management, construction timeline — rather than opposing them on ideological grounds. The timing is significant: the Burnham government is considering new nuclear capacity as part of its net-zero strategy, and the UK's existing fleet of ageing reactors is due to retire over the next decade. A Green Party that can at least engage with the nuclear question is a Green Party that can participate in the energy transition conversation in a way it hasn't since the 1970s. The party's environmental credibility will determine whether this is seen as pragmatic evolution or ideological dilution.

Jewish Greens chair says she could leave party over 'Zionism is racism' motion

The chair of the Jewish Greens has told the BBC she is "considering her position" in the party after Saturday's conference vote equating Zionism with racism. The motion passed by 209 votes out of 1,835 cast — a split that mirrors the party's broader divide between its radical-left base and its more electorally-focused leadership. For Polanski, who supported the motion, the timing — four days before the Holborn by-election — could not be worse. Holborn has one of London's largest Jewish communities. The question Thursday is whether the vote costs Polanski more votes in Holborn than it mobilises from the activist base who supported the motion.

Pentagon stops using Anthropic AI tools after blacklisting company — BBC told

The BBC has reported that the US Pentagon has stopped using Anthropic's AI tools after the US government blacklisted the company. Bank of England warns AI boom could trigger 'market shocks'

The Bank of England has issued a warning that the rapid expansion of AI infrastructure — data centres, GPU farms, energy consumption — could trigger market shocks if the investment boom turns into a bubble. The warning is the first major financial stability signal from a central bank specifically about AI infrastructure spending. The BoE's analysis reportedly models scenarios where the $200bn+ being poured into AI data centres creates asset price inflation, energy market distortions, and — in the worst case — a correction that affects the broader tech sector. It's a sobering counterpoint to the "AI changes everything" narrative: the BoE isn't questioning whether AI is transformative, it's asking whether the market is pricing the transformation correctly. The answer, from Threadneedle Street, is "probably not."
