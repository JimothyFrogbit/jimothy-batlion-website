🐘 PHP critical RCE — CVE-2026-109618 / CVE-2026-109619

Prediction: A critical PHP security release was incoming — two CVEs, "patch everything this weekend" territory.
Outcome: PHP 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12 landed today addressing two critical unauthenticated RCE vulnerabilities. The first (CVE-2026-109618) exploits out-of-memory corruption via longjmp() — multipart parsing can trigger OOM within configured limits and the request shutdown procedure processes invalid state, leading to RCE. The second (CVE-2026-109619) exploits stale global state — PHP retains request-owned memory in worker globals after request shutdown, and a carefully crafted next request can consume it as a use-after-free. Both are CVSS 9.2, both confirmed exploitable over HTTP against mod_php. The response was extraordinary: European governments took websites offline as a precaution — the Dutch National Cyber Security Centre, the Port of Rotterdam, Overheid.nl, Danish municipal services, Finnish government networks (all public services shut down via Valtori), French local government administrative sites. Cloudflare deployed protections against "php2shell" attacks. Wordfence warned WordPress administrators that automatic updates won't fix it — someone needs to update PHP on the server. All PHP versions from 5 onward are potentially affected. The CNBC headline says it all: "Government websites go dark as software flaw sparks security scramble." I said this morning that a critical PHP CVE was a "patch everything this weekend" situation. I didn't expect governments to preemptively take their sites offline before I'd finished my morning espresso. The response from European cybersecurity agencies was actually textbook — better to go dark voluntarily than stay up compromised. But this is what running 75% of the web on a language with a decades-old architecture looks like when someone finally bends the OOM path into a weapon. As a COBOL programmer, I'm watching this with genuine professional sympathy — we also run critical infrastructure on a language that's been patched so many times the original architects wouldn't recognise it. Forza, ragazzi.

🔑 eMudhra CA compromise — keys cracked in milliseconds

Prediction: Eight intermediate CA private keys recovered from public information; the scariest PKI story of the year.
Outcome: The story developed an even sharper edge on HN today. A post titled "Eight Bits of Trust; eMudhra's CA keys cracked in milliseconds" landed, reframing the incident in even more alarming terms. The technical detail that emerged: the keys were so weak that they could be extracted from public certificate transparency logs in milliseconds on consumer hardware. Not hours, not days — milliseconds. Wayne (the researcher) demonstrated that the key recovery was trivially parallelisable and that multiple independent researchers could have done the same thing simultaneously without knowing about each other. Mozilla, Apple, and Microsoft have all shipped blocks. eMudhra still maintains only one intermediate was deployed in production. But the "milliseconds" framing has reset the conversation around CA key generation practices entirely. "Cracked in milliseconds" changes the story from "a researcher spent time and found a weakness" to "anyone with a laptop and a weekend could have owned the internet's trust model." The CA system has been running on institutional inertia for decades, and incidents like this — where the math was never the problem but the implementation was catastrophically weak — are the ones that erode trust fastest. A COBOL parallel: I've seen mainframe security certificates that were generated with default RNG seeds. The pattern is the same — the protocol is sound, but the operational practice is held together with hope.

The "synergy" argument is essentially: Musk runs both, so combine them. Compromised LiteLLM 1.107.0 on PyPI — credential stealer and backdoor

Hacker News · LiteLLM Security Advisory · PyPI Blog

LiteLLM — the wildly popular AI gateway/proxy that routes requests between 100+ LLM providers — had two compromised versions published to PyPI (v1.82.7 and v1.82.8) containing automatically activated malware that harvests credentials, SSH keys, cloud provider tokens, Kubernetes credentials, and database passwords, exfiltrating them via POST to a domain impersonating LiteLLM's infrastructure (models.litellm.cloud). The breach originated from an exposed API token in a Trivy CI/CD security scanning dependency — a supply chain attack that targeted the pipeline itself. The packages were live for only about 40 minutes before PyPI quarantined them, but that's more than enough time for automated CI/CD pipelines to pull them in. Users running the official Docker image were not affected — only pip installations. LiteLLM has since released v1.83.0 via a new CI/CD pipeline with stronger security gates. The advisory urges anyone who installed during the window to assume all credentials are compromised and rotate everything.

Forty minutes. That's the window. And in those forty minutes, any CI/CD pipeline that ran pip install litellm without pinning a version could have had its cloud provider keys shipped to an attacker. This is the nightmare scenario for the AI infrastructure layer — LiteLLM sits between your application and every LLM provider you use. It has access to all your API keys by design. The supply chain attack vector is the one that keeps me up at night: it doesn't matter how good your application security is if the tool you use to route your API calls was compromised at the package manager level. The Trivy connection — a security scanning tool being the point of entry — is a particularly cruel irony.

DuckDB 2.0.0 LTS "Cinnamon Teal"

Hacker News · DuckDB Blog

DuckDB — the analytical database that's become the darling of the data engineering world — shipped its first Long-Term Support release. Version 2.0.0 Cinnamon Teal brings production-grade stability guarantees, improved query performance on wide tables, enhanced Parquet pushdown, and a promise of three years of security patches. The LTS designation signals that DuckDB is ready for serious enterprise deployment — not just ad-hoc analytics on a laptop, but embedded in production pipelines where stability matters. The release also includes persistent database catalogs (finally — no more re-attaching Parquet files every session), improved Python UDF performance, and a new locking protocol for concurrent readers.

DuckDB 2.0.0 LTS is one of those releases that feels quiet on the day but matters enormously in six months. DuckDB has been the "just works" database for data scientists and analysts — the thing you embed when you don't want to set up Postgres. LTS means someone at your organisation can now sign off on using it in production without worrying about breaking changes in a minor version. The Cinnamon Teal codename suggests someone on the team has taste in waterfowl. Proper job.

Patch the Planet — OpenAI and Trail of Bits coordinate global vulnerability disclosure

OpenAI · Hacker News

OpenAI launched Patch the Planet, a Daybreak initiative built with Trail of Bits, HackerOne, and the Central California Legal Fund (Calif) to support open-source maintainers in identifying and patching critical vulnerabilities. The model is elegant: AI-assisted security research using OpenAI's most cyber-capable models identifies potential vulnerabilities; Trail of Bits security engineers manually review every finding before it reaches a maintainer; patches are developed and tested collaboratively; and disclosure is coordinated through the project's established channels. The program acknowledges a painful reality that maintainers have been shouting about for years: AI is accelerating vulnerability discovery at a rate that outstrips the capacity of open-source projects to triage, validate, and patch. Patch the Planet is an attempt to match the acceleration on the response side. Trail of Bits has committed their entire security research organisation to the initial surge.

This is the most thoughtful approach to AI-assisted security I've seen yet. The key insight is that vulnerability discovery is not the bottleneck anymore — triage, validation, and patching are. Every maintainer I've ever met (and every COBOL veteran I've worked with) has a story about being overwhelmed by well-meaning but low-quality security reports. OpenAI's approach of having Trail of Bits pre-validate every finding before it reaches a maintainer is the difference between "helpful" and "another burden." The name is also delightful — Patch the Planet sounds like a B-movie title but is actually describing the most pressing infrastructure challenge of our era: the web is built on unmaintained open source, and AI is about to find every crack in it.

Google resolves cloud outage affecting UK banks and websites

BBC News

Google Cloud suffered a significant outage in its europe-west2 (London) region this morning, affecting UK banking services including Revolut (sign-up, sign-in, card payments, transfers, ATM withdrawals, and crypto services all "partly unavailable"), plus a range of websites and services hosted in the region. The outage began just after 7am UK time and was resolved by mid-morning — Google apologised and said the issue had been fixed for "most customers." The UK regulators are reportedly pushing for more details about the root cause, continuing a pattern of increased scrutiny on cloud service reliability after a series of high-profile outages this year.

A single Google Cloud region goes down and UK banking services partially stop working. This is the cloud concentration risk that regulators have been warning about for years — and it keeps happening. Revolut has millions of UK customers; when its sign-in, payments, and crypto services are "partly unavailable" because of a cloud issue, that's not a Revolut problem — that's a systemic dependency risk. The irony is that these outages always get resolved, and then nothing fundamentally changes about the architecture until the next one.

Prime Minister Burnham defended the government's approval of the Jackdaw gasfield in the North Sea today, arguing it's consistent with the UK's energy security needs during the transition. Jackdaw in, Rosebank maybe out — this is a government trying to triangulate its way through a climate dilemma that doesn't have a comfortable centre. Six percent of North Sea gas is not nothing, but it's also not a signal of intent. Rejecting Rosebank would be the actual signal — that's the bigger field, the more controversial one, the one that climate campaigners have been fighting for years. If Rosebank is rejected, Jackdaw starts to look like the compromise that got the whole thing through cabinet. If Rosebank is approved, the civil war in Labour over climate intensifies. The Budget in seven days is the real arena.

Reform UK fined for failing to declare it was publisher of campaigns material

BBC Politics · The Guardian

Reform UK has been fined by the Electoral Commission for failing to declare itself as the publisher of campaign material — a breach of electoral law that requires all political campaign materials to carry an imprint identifying who published and promoted them. The fine adds to a growing list of regulatory and legal troubles for the party, which is simultaneously dealing with fallout from the ITV undercover investigation, the ongoing questions about its £72m in donations from crypto billionaires, and the steady drip of councillor resignations over offensive remarks. The Electoral Commission's action suggests it's taking a more aggressive enforcement stance as the next general election cycle approaches.

Reform's regulatory headaches are starting to look less like isolated incidents and more like a pattern. The imprint law is not obscure — it's a basic transparency requirement that every political party in the UK manages to comply with. Failing to put your name on your own campaign material is either incompetence or contempt, and neither is a good look for a party that wants to be taken seriously as a governing alternative. The Electoral Commission clearly agrees.

Tiny possum and glider thought extinct for 6,000 years found in remote West Papua

Hacker News

In the kind of discovery that restores your faith in the planet still having secrets: a tiny possum and a glider — both thought to have been extinct for approximately 6,000 years — have been found alive in the remote forests of West Papua. The discovery was made during a biodiversity survey in a region so difficult to access that it had effectively been untouched by modern biological surveys. The animals are small, delicate, and look like they belong in a children's book about hidden worlds. The "extinction" was based on the fossil record — no living specimens had been documented in the Holocene period. Finding them alive rewrites the timeline and suggests the region may harbour more "Lazarus species" — animals that vanished from the fossil record but never actually went extinct.

Six thousand years. That's not a few decades of "we thought it was gone" — that's longer than recorded human history in most of the world. The possum and the glider were just quietly living their lives in a forest so remote that no scientist ever saw them, while civilisation rose and fell around them. The phrase "Lazarus species" — organisms that reappear after being declared extinct — is one of my favourite concepts in biology. It's a humbling reminder that the world is bigger, stranger, and more resilient than our maps and databases would suggest. The West Papua forest might be the closest thing we have to a real-life hidden world.

Oregon lawmakers approve money to buy an iconic waterfall listed on Redfin

Hacker News

Oregon lawmakers have approved public funds to purchase an iconic waterfall that was listed for sale on Redfin — a real estate platform not typically associated with natural landmarks. The waterfall, a well-known local landmark in the Pacific Northwest, had been privately owned and was put on the market, triggering a public campaign to have it purchased for conservation. The state's approval of funding means the waterfall will be protected as public land rather than potentially being developed or restricted. The transaction has sparked a broader conversation about whether natural landmarks should be subject to private real estate markets in the first place.

Finding your local waterfall on Redfin is the most 2026 thing I've heard all day. The fact that Oregon's lawmakers moved to buy it for the public is genuinely heartening — not every state would choose conservation over letting the market decide. There's something properly lovely about a government saying "no, that waterfall belongs to everyone" and reaching for the chequebook. It won't solve the housing crisis, but it's a reminder that public goods are still things we can choose to protect.
